## Worked Example

*Study this example before attempting Tier 1. After reading it, close it and try to recall the key steps from memory before moving on.*

**Problem:** In 2010, a junior engineer builds a full-stack web app over four months — database, API, front end, deployed on a personal server. She posts it on GitHub. In 2025, a junior engineer builds the same type of app in two days using Claude Code and Cursor, then posts it on GitHub. A recruiter sees both GitHub profiles. What has changed, and what does the Spence mechanism predict about each engineer's signal?

**Approach:**
Step 1: Define the Spence mechanism — a signal works because its *cost-structure* correlates with the underlying productive capacity being signaled. High cost to fake = informative signal.
Step 2: Estimate the cost of producing the 2010 signal: multi-weekend effort, debugging unfamiliar tools, real perseverance required. The cost correlated with engineering competence.
Step 3: Estimate the cost of producing the 2025 signal: two days, AI-guided debugging, one-click deployment. The cost has fallen dramatically.
Step 4: Apply the separating vs. pooling equilibrium concept. When *all* candidates can produce the same signal cheaply, the signal stops sorting (pooling equilibrium). The recruiter cannot distinguish two-day Claude Code projects from four-month craft projects by looking at the GitHub profile.

**Answer:** The 2010 GitHub signal was in a separating equilibrium — it successfully differentiated candidates by productive capacity. The 2025 GitHub signal has pooled — 82% of developers use AI tools, so the repository no longer tells the recruiter anything about the underlying work. The 2025 engineer needs different costly signals: evidence of Ideate (a documented user problem), Brand (a coherent audience and voice), and Ship (real users, feedback loops).

**What to notice:** The Spence mechanism does not say GitHub is worthless. It says the signal is no longer *separating*. The evidence of productive capacity has to move to the signals that AI tooling has not cheapened.

**Ex 3**
*Model answer:* A separating equilibrium is a state in which a signal successfully sorts candidates — people with different underlying capacities produce the signal at different rates or with different effort, so the signal is informative. A pooling equilibrium is the opposite: when everyone can produce the signal cheaply, it stops distinguishing, and the employer cannot tell from the signal who is more capable. An example of a current separating signal for software engineers: a deployed production system that has handled real-scale traffic, because AI tools can generate code but cannot fake production experience.
*What a strong answer includes:*
- The cost-structure argument — why a signal separates, not just that it does
- The pooling equilibrium as a dynamic state, not a permanent one — signals can move between states
*Chapter reference:* Part 2: Signaling Theory — Separating vs. Pooling Equilibrium

**Ex 16 — Synthesis**
*Model answer:* Brand as a four-verb activity is strategic construction: you make decisions about audience, positioning, and voice that you would not make by default. Archetype as a descriptive system is discovery: you find the pattern that is already in your work. These are not contradictory because Brand construction *requires* accurate self-description to be sustainable. An archetype that is invented for strategic effect but does not match the actual pattern of your work is exhausting to maintain — customers eventually feel the strain. The recognition asset (the model customers build of who you are) is built by accumulation of consistent touchpoints; it can only accumulate if the archetype is authentic enough to produce consistent behavior naturally. Brand without archetype is a set of arbitrary style decisions with no strategic foundation. Archetype without Brand is an identity that never becomes a separating signal because it is never strategically deployed.
*Common error:* A surface answer says "they work together" without explaining the mechanism. The stronger answer uses "recognition asset" to show why descriptive accuracy is load-bearing for constructed positioning.
